**Status on 2026-11-10:** **NO-GO**, release target only. No v1.0.0 installer, signed media or fully functional MCP write integration is currently qualified.  
**Program:** [RC integration #180](https://github.com/Knapp-Kevin/sonic-rift/issues/180). **No autonomous scheduled monitoring is authorized.**  
**Previous public baseline:** signed Windows v0.9.1 prerelease.  
**Candidate tag (not yet created):** `v1.0.0-rc.1`.

## Release promise, not just feature names

A user can start Sonic Rift locally, generate actual **Speech, Music and Sounds** with installed models, edit and mix those sources in Studio, and export master/stems that carry C2PA-valid signed Content Credentials. The **same operations** are accessible via a versioned authenticated local HTTP API and a real MCP client, with app-owned authorization, job tracking, resource control, and verified source provenance. Agents do not gain ambient host privileges, arbitrary filesystem access, model installation or cloud billing.

If any one of these fundamental outcomes is unproven, status remains NO-GO. A successfully imported Python module, a merged PR, or `mergeable: true` is not a demonstration of an end-to-end product.

## Required internal service boundary

`SonicController` (name provisional) is the **single app-owned authority**, never a new inference engine. The GUI, HTTP API and MCP adapter must call the same typed versioned contracts. The current `core/agent_queue.py` persists only **non-sensitive scheduling metadata** and enforces single-worker admission; it cannot authorize an agent or run a model by itself.

**Contract candidates for API + MCP parity** (proposed, NOT implemented yet):

- **Read-only:** `capabilities`, `app_status`, `models_list`, `projects_list`, `project_inspect`, `artifact_inspect`, `provenance_inspect`, `provenance_verify`, `job_status`.
- **Owner-approved:** `generation_plan`, `job_submit` (Speech/Music/SFX), `job_cancel`, `project_create`, `track_add`, `clip_import`, `clip_place`, `clip_split`, `clip_duplicate`, `clip_update`, `track_mix_update`, `project_undo`, `project_redo`, `project_save`, `studio_export`.
- **Owner approval only in application UI:** issue/revoke a **short-lived, scope/model/project/expected-revision-bound capability**, never allow an agent to self-authorize via a tool. All write requests verify, consume or explicitly bind an authorized grant server-side. Auth/permission denials and audit logs are bounded and private.
- **Contract restrictions:** no raw prompt in response, no arbitrary path, shell command, remote URL, download, installed model mutation or unbounded raw audio in MCP context. Use opaque handles and actual digest-bearing artifact receipts.
- **Preview and direct speech streaming:** streaming PCM is a live transport, not a signed downloadable Content Credential. Save/verify a finished artifact with C2PA, and clearly distinguish the stream's unverified state. No format promises until exact native C2PA SDK confirms ability to bind WAV/MP3/OGG without changing audio contents.

An HTTP endpoint is production-ready only when the **same authorized operation works from MCP and GUI**, and negative tests prove denied/stale requests do no work. Do not extend the existing `/v1/speech` through a generic unrestricted agent proxy.

## Version pins and compatibility validation

- MCP Python SDK [stable v2.3.0](https://github.com/modelcontextprotocol/python-sdk/releases/tag/v2.3.0) is the **proposed isolated adapter qualification pin**, not an app/engine dependency until a complete reproducible lock and Windows handshake exist. The official v2 API uses `MCPServer` and `Client(StdioServerParameters(...))`. The script `scripts/qualify_mcp_stage_a_v2.py` tests exactly four Stage A tools against the actual stdio server; its `--require-app` mode also verifies an authenticated live app, without granting execution.
- C2PA [specification 2.5](https://spec.c2pa.org/specifications/specifications/2.5/index.html), and audio/music-specific guidance; use a vetted/pinned `c2pa-python` native SDK whose **installed** Reader and Builder support + true signed-file round trip are proven in Windows tests. Do not invent incompatible C2PA assertion JSON or equate self-signed test certs with trusted issuer.
- Separate private forensic appendix: reviewed authenticated encryption and key lifecycle, public minimum disclosure always independently readable. Distinguish model evidence, signature trust, copyright/license, human contribution and artistic value.

## Release test and evidence matrix

**G0 Repository/reproducibility:** input and lock pins, license audit, source identity, dependency manifests, clean `[skip ci]` workflow. Independent review. Merge order [#127](https://github.com/Knapp-Kevin/sonic-rift/pull/127), [#175](https://github.com/Knapp-Kevin/sonic-rift/pull/175), [#178](https://github.com/Knapp-Kevin/sonic-rift/pull/178) and staged UI/MCP branches only after their own receipts.

**G1 Real generation and Studio:** Windows RTX/CPU test install; 3 actual generation engines, model switching, preview, multi-track edits with undo/redo, audible master and stems; measure disk/VRAM/timing and validate original source unchanged.

**G2 Protocols:** exact `mcp==2.3.0` in separate adapter env. Real stdio list/call handshake, app protected auth status, denied anonymous reads, malformed input and repeated plans; then authorized Speech/Music/SFX generation/status/cancel and Studio operations from local Claude/Codex or other supported clients. Hosted ChatGPT requires a separately designed and security-reviewed transport; it **cannot reach private loopback directly**.

**G3 Provenance:** synthetic and real multi-model/mixed human/unknown examples, distinct event IDs for identical bytes, no inferred human provenance; actual signed C2PA credential embedded and independently validated in **each** export format and each standalone output path. Tamper, stripping, missing signer, invalid cert, private prompts, failed crypto, crash recovery, no key leakage, sample and perceptual parity.

**G4 Reliability/security:** permission grant/revoke/replay, stale revisions, two API/MCP workers racing GPU, cancellation, shutdown, restart, disk and path attacks, import and embedded metadata corruption, fail-closed transaction logs.

**G5 Distribution:** clean v1.0.0-rc.1 source/installer artifact at exact reviewed SHA, signed Windows installer, SHA-256 and SBOM, real launch/uninstall and upgrade from v0.9.1, complete release notes, owner listening, independent review and explicit GO.

## Safe commands for a qualified Windows environment

No instructions below silently install models, create signing keys, call paid CI or tag a release.

```powershell
# Use a clean isolated checkout and disposable user profile for tests.
python -m unittest -v tests.test_agent_queue tests.test_agent_jobs tests.test_agent_gateway tests.test_sonic_mcp_adapter tests.test_mcp_v2_gate
python -m unittest discover -s tests

# Separately install the audited/pinned official mcp==2.3.0 SDK in an adapter-only env.
python scripts/qualify_mcp_stage_a_v2.py
python scripts/qualify_mcp_stage_a_v2.py --require-app

# C2PA: the following only probes an installed SDK, never signs anything.
python scripts/provenance_c2pa_sdk_probe.py
```

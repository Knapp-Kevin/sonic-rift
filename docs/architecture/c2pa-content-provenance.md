# Sonic Rift media provenance and C2PA Content Credentials

**Date:** 2026-11-10  
**Status:** Proposed architecture plus a draft implementation of local generation events and **unsigned export disclosure**. Native C2PA signing/embedding, private-data encryption and Windows qualification are **not yet implemented or passed**.  
**Authority:** Owner product direction; formal owner signing-identity and release-policy decision remains open in [#174](https://github.com/Knapp-Kevin/sonic-rift/issues/174).  
**Tracker:** [P0 provenance epic #169](https://github.com/Knapp-Kevin/sonic-rift/issues/169), [source capture #170](https://github.com/Knapp-Kevin/sonic-rift/issues/170), [SDK qualification #171](https://github.com/Knapp-Kevin/sonic-rift/issues/171), [export credentials #172](https://github.com/Knapp-Kevin/sonic-rift/issues/172), [private forensic data #173](https://github.com/Knapp-Kevin/sonic-rift/issues/173).

## Purpose

Every published Sonic Rift audio export should disclose *whether and how AI was involved* and offer a traceable, cryptographically verifiable chain of its contributors. Audio made from several AI models and a real person must preserve all contributors rather than assign a misleading single-origin binary flag.

Provenance is **not** a judgement of quality, authorship, copyright, licensing, or artistic worth. Absence of credentials is **not** evidence of human origin. A signature proves binding, signer and tamper-evidence, not that every factual claim the signer made is true.

### Authority and alignment

- [C2PA technical specification 2.5](https://spec.c2pa.org/specifications/specifications/2.5/specs/C2PA_Specification.html), October 2026. Normative rules for claims, assertions, signing, trust, validation and embedded WAV/MP3/OGG manifests.
- [C2PA music guidance 2.4](https://spec.c2pa.org/specifications/specifications/2.4/music/guidance_applying_content_credential_music_assets.html), in particular separate AI instrumental and human vocal ingredients, signed final master/stem history, provenance at track/stem level.
- [C2PA `c2pa.ai-disclosure`](https://spec.c2pa.org/specifications/specifications/2.5/specs/C2PA_Specification.html#_ai_disclosure), `digitalSourceType`, `c2pa.actions.v2`, `c2pa.ingredient.v3` and audio temporal regions. Use the actual normative field schemas, not a hand-authored invented C2PA manifest.
- [Agentic AI Foundation, Observability & Traceability](https://github.com/aaif/wg-observability-and-traceability): useful for attribution of **agent tool calls and actions**, not a substitute for a music/file-provenance standard.
- [contentauth/c2pa-python](https://github.com/contentauth/c2pa-python): maintained Python bindings for reading and signing. Dual MIT/Apache-2.0 licensing; native binary, Windows wheel, supported audio format and exact SDK version need qualification before adoption.

## Verified current code and gaps

`core/music/service.py` retains model repo ID, engine, revision, source revision, seed and request parameters when saving a take. `core/soundscape/assets.py` stores library asset source fields and a file checksum; a checksum check protects audio bytes against accidental change, **but does not authenticate the generator or index record**.

`core/audio_project_media.py` has a content-addressed WAV for narration takes but does not persist generator/capture attestation. Existing voice takes therefore have **unknown** origin. `core/audio_project_export.py` currently emits mastered WAV/OGG/MP3, stems and an *unsigned* `manifest.json`; it is **not a C2PA Content Credential**. The `AudioProject` schema is version 1, so new provenance must not break loading older projects.

### Classification contract

| Origin | When it may be asserted | When not to assert |
|---|---|---|
| `ai_generated` | App directly observes an AI model generate source audio and records engine/model evidence; or a third-party credential validates | Filename, waveform analysis, user-entered model label, missing signature |
| `non_ai_synthesis` | Known procedural sound synthesis with local evidence | Assuming this means human performance |
| `human_capture` | Identified capture event and an appropriate attestable origin/identity with explicit confidence level | Missing metadata, imported WAV, human-sounding synthesis |
| `unknown` | No verified creation history, conflicting evidence, old assets, untrusted imports | Never translate this to `human` or `non_ai` |
| `mixed_ai_and_other` | Final output has at least one AI ingredient and another non-AI/unknown ingredient | Claiming the whole master was generated by one model |

The **source-origin inventory** (`core/media_provenance.py`) remains intentionally *unsigned*. New Sound/Music assets carry explicit generation-time `source_event` records with output digest binding; the successful Studio narration generator writes a local `.origin.json` next to its content-addressed voice WAV. Plain narration imports and older assets without recorded creation events remain **unknown**, even if a legacy engine label names ACE-Step or MOSS. Source hashes and project IDs are internal linkable identifiers and **must not automatically become public metadata**. The output `manifest.json` now includes a minimal `provenance_disclosure` and actual exported-file SHA-256 hashes. It explicitly reports `c2pa_signed=false` and `c2pa_embedded=false`; the manifest is **not** a C2PA credential and is not itself signed.

## Proposed end-to-end dataflow

1. **At creation/import:** App-owned source registry records output digest, mode of origin, actual engine/model revision when present, timestamps, creator/identity evidence if consented, source credential validation, and operations. Source records are immutable/auditable at the event layer; revisions append rather than overwrite the prior record. Import C2PA only after full signature/hash/trust validation, otherwise classify origin as unknown/unverified.
2. **At editing:** Studio clip trim, split, duplicate, placement, fading and mixing reference source record IDs and integer frame ranges. Multiple models have independent ingredient records; no model can overwrite the attribution of other source contributions.
3. **At export:** Build a graph with the exported master as a new creation and imported/generated stems as ingredients. Represent mixed, manual editing, non-generative DSP, AI voice/music/SFX generation and optional regional AI edits using the appropriate C2PA action/source type; do not label manual mixing as generative simply because an ingredient was generative.
4. **Public signed claim:** Minimum visible AI disclosure, ingredient ancestry and model family as demonstrable, app/version and provenance assertions; no prompts, lyrics, private voice references, local paths, user identity or seeds by default. `c2pa.ai-disclosure` may carry additional structured model and human-oversight information where the SDK supports the spec.
5. **Separate encrypted private appendix:** A future opt-in, authenticated AES-GCM record for prompts and detailed settings/forensic proofs, with owner-managed key lifecycle, redaction, retention and optional public hash commitment. The **main C2PA manifest must remain unencrypted**, otherwise standard validators cannot read it.
6. **Sign, bind, validate, publish:** Use reviewed C2PA SDK and production-approved signing credentials, verify every completed output with an independent validator, then atomically publish. A failed mandatory signing/binding/verification step aborts the publish. Format-specific embedding must preserve the audio signal: WAV RIFF `C2PA` chunk, MP3 ID3 GEOB, OGG Vorbis per the supported 2.5 mechanism. Verify actual SDK support before enabling each.
7. **Future local MCP:** A permitted agent may request actions or generation; app-owned handlers attest actual model operation and authority. Do not trust agent-supplied arbitrary `made_by_human` or `model_id` assertions.

## Threat and failure model

- **Forged local index:** `engine` and `model` fields may be user-modified; even matching SHA-256 of media is not a trusted attestation. Mark the local claim's assurance level; require actual event or signed credential to upgrade it.
- **Metadata removed by distribution:** Transcoding, stripping and publication may remove C2PA. A missing manifest is `missing`, not proof of non-AI. Retain a sidecar/receipt with the release where appropriate; no claim of indestructible embedded provenance.
- **Tampering, expired or untrusted signer:** Display `invalid`, `untrusted`, `expired` separately. A self-signed dev cert does not establish publicly trusted identity.
- **Sensitive information and correlation:** Even hashes, timestamps, model details or cross-linked identifiers can reveal identities. Public profile requires privacy review; no default user/system/prompt metadata.
- **Key custody:** No embedded shared signing/encryption secret. Test keys never count as production trust. Offline Windows builds and explicit trust-anchor update/rotation requirements.
- **Export failure:** Preserve stage-directory atomicity and cancellation behavior; never publish uncredentialed output while claiming success under a mandatory credential policy.
- **Audio fidelity:** No inaudible watermark by default because even a subtle watermark edits samples. Inserting container metadata must not change decoded PCM; measure exact WAV sample parity and MP3/OGG decoded parity compared with same-codec baseline. Stem and master timing/level tests remain release gates.
- **Authenticity scope:** No metadata can forensically establish facts that were never captured; C2PA is **tamper-evident attestations**, not a universal AI-content detector.

## Implemented-but-unqualified draft checkpoint (2026-11-10)

- `core/soundscape/assets.py:Asset.source_event`, `core/music/service.py:keep`, and Sounds `keep_sound_take` capture the method, known model and audio digest *when a local generation completes and the take is kept*. Old asset indexes load without that new optional field.
- `core/audio_project_media.py:import_generated_voice_take` writes a bounded local origin sidecar tied to the real WAV digest. The ordinary `import_voice_take` path does not mark imports as AI or human. This deliberately records the AI nature of the actual Studio TTS worker without claiming a model revision that the current interface does not expose.
- `core/media_provenance.py` aggregates all clips, frames and source categories for internal assessment and emits a privacy-minimized public summary with `unsigned_local_claims_not_c2pa`.
- `core/audio_project_export.py` stages the `provenance_disclosure` and SHA-256 hashes of each encoded master and stem in the existing JSON manifest before publishing the output directory. Original PCM and project JSON remain untouched. These hashes are **not authenticated** against a signing identity; a malicious editor can also change the unsigned manifest.
- `scripts/provenance_c2pa_sdk_probe.py` performs a read-only capability check of installed `c2pa-python`, querying `Reader.get_supported_mime_types()` and `Builder.get_supported_mime_types()` plus native version. Candidate SDK documentation at [c2pa-python v0.38.0](https://contentauth.github.io/c2pa-python/api/c2pa/c2pa/index.html) documents these APIs. This probe **does not install anything, sign, or verify media**.
- Existing standalone Speech, Music, Sound and API exports must be enumerated and covered by the real signed-export gate as well. No claim of complete output-surface coverage is warranted yet.
- **Windows/Qt tests and actual C2PA SDK audio round-trips have not run.** The new work is draft/HOLD and not production disclosure.

## Source-identity collision and output-safety correction (2026-11-10)

**The source fingerprint is not an event identity.** In Studio v1, two narration clips containing byte-identical WAV can share the same `voice_<sha256>` media ID even when one was generated by the app and another came from a user import. A global per-hash AI sidecar cannot truthfully distinguish those histories. The draft now writes a conservative `.origin-ambiguous` marker on cross-context reuse and refuses to promote **either clip** to a recorded-AI claim. Deleting/recreating a JSON sidecar does not silently remove that ambiguity marker. The source audio stays usable. This deliberately prefers a false-negative `unknown` over false AI or human attribution. The local marker is **unsigned, user-modifiable evidence**, not robust forensic tamper protection.

The real long-term fix is a separate **creation event ID/claim reference per clip or composition ingredient**, tied to an immutable source hash and signed event graph. Because existing `AudioProject` v1 stores only the media asset ID, that requires an explicitly reviewed schema/sidecar migration and correct behavior across save/reopen, undo/redo, clip split/duplicate, imports, concurrent workers, and C2PA ingredient mapping. A file digest alone cannot solve it.

This draft also applies consistent source-asset filename/ID binding in `AssetLibrary.path/verify/export/remove` and `ProjectMedia.resolve`. A forged local library index must not cause an arbitrary external read, export, or delete, or substitute a different Sound asset under an existing clip ID. The code now exclusively creates digest-named voice WAVs and their origin metadata rather than replacing previously existing paths. **Verify these atomic hardlink operations on the Windows release target and supported storage filesystems**. Unsupported filesystems must fail safely and be designed for explicitly; passing static review does not establish Windows correctness.

The unsigned Studio export manifest also now contains `stem_provenance_disclosures` indexed by exported stem filenames. This reports per-stem AI/unknown categories, known model IDs and clip-origin counts **without prompts or private source paths**. These JSON summaries and their output-file hashes still have **no independent signing authority**, and metadata editing remains possible until the native C2PA stage.

## Delivery gates

**Gate 0: inventory.** Pure service inventories source events bound to known local audio files; any unrecorded old/imported source remains unknown. Synthetic tests cover mixed models, missing source, conflict, unrendered clips, duplicates and private fields. **Code present in draft, tests not yet executed on Windows.**

**Gate 1: capture.** Generation-time Sound/Music/Studio narration source records are now coded in draft; import/legacy origin is unknown. Add full session-level provenance, independent imported C2PA validation, event-log integrity/trust and source-to-action chains before calling the gate complete. Existing v1 project format is unchanged; run save/reopen, audio and Windows tests.

**Gate 2: signing proof.** C2PA 2.5 API and native version pin, clean Windows install, sample WAV + MP3 + OGG file signing and independent validation with test identity, backward compatibility, trust-state checks, no model downloads.

**Gate 3: integrated export.** Public signed per-stem and final master metadata, private data never leaked; every format tested with independent validator and unchanged audio samples. Round-trip and manifest-stripping tests.

**Gate 4: production.** Owner-approved signing identity, trustworthy certificate, keys stored outside repo, key rotation/recovery, privacy controls, UI review, on-device listening, Windows release evidence.

### Explicit unresolved owner decisions

See [#174](https://github.com/Knapp-Kevin/sonic-rift/issues/174): production signing principal; how much model identity is public; who holds private encryption keys; and whether a missing trusted signer must block release exports or allows a prominent unsigned disclosure. **Do not silently choose a public attester or downgrade policy.**

**No automatic merge, deployment, model installation, CI Actions or credential publication is authorized by this proposed architecture.**
